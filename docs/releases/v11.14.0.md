# EchoSpeak 11.14.0 — A harness you can check

> **Status:** source in `main` (this version bump). Installers aren't built or published yet.
> - **Windows:** `apps/desktop/scripts/release-windows.ps1 -Publish` (signing key needed) builds the signed
>   installers and `latest.json` for the in-app updater.
> - **Linux:** `apps/desktop/scripts/build-linux.sh` builds the AppImage, `.deb` and `.rpm`. Linux builds don't
>   update themselves.

11.14.0 is the harness work of 14–16 November: what the agent loop does when models, tools and servers misbehave,
and how that was measured with real local models.

## What changes for you

| Area | Before | Now |
|---|---|---|
| Terminal on Linux | Docker needs the root-equivalent `docker` group, so commands ran directly on your PC, each asking first | Commands run in a **bubblewrap sandbox**: the system is read-only and only the workspace is writable; `~/.ssh`, keyrings, browser profiles and `/run/user` are hidden; no network unless allowed. If the sandbox can't start, nothing runs unconfined silently. |
| Stop | A running command kept going for up to 15 minutes, and background work survived | Stop ends the command and the task's own background work. **Dev servers keep running**, are listed, and stop on request (`POST /lean/terminal/stop-servers`, or Stop everything with servers). Commands a crash left running end at the next start. |
| Approvals | Two read-only calls in one step ran without the approval they needed, and before a write listed earlier | Every "ask" reaches you; calls run in the model's order. |
| MCP | A timeout or lost connection counted as success; a running server could add tools unapproved | Failures are failures, a call lost in flight is marked uncertain, and changed tools wait for re-approval. |
| Secrets | Arguments with secrets reached the run journal and saved tool runs; MCP tokens weren't redacted | Both are redacted. The tool still gets the real value. |
| Blank or failed replies | "I couldn't put together a reply" for every cause; a budget limit looked like a crash; one 429 or dropped connection ended the task | The cause is named (incomplete stream, full context window, output limit); `no_answer` and `budget` are explicit outcomes; passing failures retry twice, only before anything was shown. |
| False claims | "I corrected `calc.py`" with no edit passed | Caught: the reply gets a correction note. |
| LM Studio | Embedding models and the served context window used older or no APIs | REST v1, with v0 as fallback. |

## Evidence

- **Tests:** 1,534 passed across the 110 related backend test files. Every fix has a regression test that fails on
  the code before it.
- **Live, `qwen3.5:9b` on Ollama 0.40.16, 15 tasks × 2, independent judge:** 8.88 → **9.07** (held-out 9.04 →
  9.17); 90% of tasks done right; 0 critical findings.

## Also

- **Build:** `build-linux.sh --bundles appimage` no longer stops silently after the backend.
- **CI:** the Website workflow failed on every merge to `main` after the repository became private ("Get Pages site
  failed", HTTP 404). It now builds the site every time and publishes only when GitHub Pages is enabled.
- **Removed:** the dead `GET /stream/{request_id}` route.

## Known gaps

These are ranked in the architecture review §4:
- budgets (approval waits count against time);
- secret coverage for connection and OAuth tokens;
- Chat doesn't read AGENTS.md;
- duplicate legacy tools;
- three overlapping task records;
- models that hard-code the answer to an impossible test.
