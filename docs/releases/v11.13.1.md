## Codex follow-up: usage refresh and Git diagnostics

The reported project is ChatHub. The previous installed window reproduced the
generic Git worktree exit 128. Its cause is **still unresolved**. ChatHub has a
valid committed HEAD; direct Git, source provisioning and the rebuilt compiled
backend all create an isolated worktree successfully. These checks do not prove
that the owner's installed-window failure is fixed. No automatic commit, Git
configuration change, reset or copy of local source edits was used.

Implemented in this candidate:

- Codex account metadata refreshes on Code entry and every five minutes while
  selected. Connected session polling uses a five-minute, coalesced fallback to
  `account/rateLimits/read`; official `account/rateLimits/updated` events still
  update immediately. Focus refresh is throttled; timers stop on unmount.
- The newest `observed_at` wins between account and session observations across
  the workspace, picker and connection panel. Old session data can no longer
  hide a newer account check. Failed reads retain the last values/timestamp and
  show an explicit refresh failure. Missing allowances never become zero.
- The connection panel has a working **Refresh limits** action. The consolidated
  Usage view reloads every five minutes while open; connected Codex reads reuse
  the same throttled adapter. Disconnected consolidated accounts remain cached
  until an account check, such as Code entry or Refresh limits.
- Git failures retain a bounded, stored-secret-redacted diagnostic instead of
  discarding stderr. The owner API permits enough text to display the reason.
  Existing repository/HEAD/ownership/lock guidance remains.

Five minutes is Echo's fallback policy, as requested by the owner. The
[official Codex app-server documentation](https://learn.chatgpt.com/docs/app-server)
documents read and update notifications; it does not specify this interval.

The rebuilt backend passed real ChatHub worktree provisioning, existing Codex
subscription authentication, model discovery, numeric allowance retrieval,
consolidated usage and stop. **Zero model prompts were sent**. These were compiled
API checks using disposable application state, not installed desktop acceptance.
A deliberately obstructed disposable repository produced a real worktree exit
128 and verified that its actual Git reason reaches the API. That fixture does
not identify the cause of the owner's failure.

TypeScript, 38 web tests, 16 desktop contracts and rendered manual-refresh
interaction passed. All 57 final Git/session/workbench tests passed. Fake-clock tests verify the five-minute interval,
in-flight coalescing, error retry, cleanup and newest-observation selection.
