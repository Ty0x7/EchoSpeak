# EchoSpeak 11.13.1 — Folder-first coding and sidebar polish

**Objective → Research → Environment → Verification → Adaptation → Completion.**

## Current behavior

Codex, Claude Code and ACP sessions default to **Project folder**. They work in
the selected trusted folder, including existing local files. A Git repository,
initial commit and GitHub account are not prerequisites. Echo does not initialize
Git automatically. The installed vendor runtime retains its own platform
dependencies, authentication, tools and permission behavior.

**Isolated Git worktree** is an explicit alternative for a repository with a
committed HEAD. It retains the existing raw committed-file provisioning,
dirty-source acknowledgement, isolated checkpoints and conflict-checked rollback.
An explicitly requested worktree never silently falls back to direct edits.
Existing saved sessions without a mode remain worktree sessions.

The Code composer, session panel and inbox distinguish folder sessions from
isolated worktrees. Folder mode shows Create session and no committed-HEAD
checkbox. Execution trust is remembered separately per workspace mode, so an old
worktree-only acknowledgement does not silently authorize new direct-folder work.

Session metadata stays under app data for both modes. Folder validation follows
the trusted project binding, allowing the agent to initialize Git or change its
branch later. A root-scoped lock coordinates connected external runtimes and
Workbench writers using the same folder. Stop that runtime before opening a
separate writable Workbench terminal for the folder. This is writer coordination,
not an OS sandbox or protection against unrelated programs.

Folder mode does not snapshot the whole project or require a Git checkpoint to
start a turn; large/untracked projects are not subject to the isolated snapshot
limit. Echo's automatic last-turn rollback is unavailable there. Files and
Terminal remain project operations; Git diff/branch/PR features become useful
when Git is explicitly set up. Vendor permissions still govern provider tools.

## Git can be added later

An agent can initialize Git and prepare branches/commits/PRs when the owner asks.
Echo's setup path makes none of those decisions automatically. The same folder
session survives the change. Workbench recognizes a new repository even before
its first commit. Open file/Git views refresh periodically; completed runtime
turns refresh the workspace capabilities and status. Optional worktrees become
available after committed HEAD exists. The worktree branch restrictions do not
apply to direct-folder sessions.

## Preserved functionality

- Search-first, single-column Chat/Agents navigation, compact footer utilities,
  and Code's upward-opening Working/Snoozed/Settled shelves remain.
- Codex usage retains native update events, a five-minute fallback and manual
  Refresh limits. Newest account/session observations win; failed reads preserve
  the last timestamp. Subscription allowances remain separate from API billing.
- Native Echo supports configured local/API models through its own Lean harness.
  Codex/Claude/ACP remain separate vendor runtimes rather than entering that loop.

environment/cloud tests. The failure is the unchanged
`test_cloud_models.py::test_an_echo_code_conversation_cannot_switch_to_an_api_key_model`,
which expects the superseded API-model prohibition. Current code permits that
binding. No test was altered during the research-only review.


The new candidate has not been installed by the agent. Owner acceptance should
start with an ordinary folder and Create session, then one controlled coding
task. Live inference, completed-history resumption in the fresh folder and
in-flight interruption remain unverified for this candidate. A native resume of
a no-turn Codex thread was rejected during an initial no-prompt check; transport
reconnection and historical completed-thread resume are different evidence.

The earlier installed worktree exit-128 cause was not established. It affects the
optional worktree path, which has passing source/compiled checks but still needs
installed acceptance. It no longer gates ordinary-folder sessions. Git failures
retain bounded, redacted diagnostics. Claude's earlier weekly-limit rejection is
historical; no new inference attempt was made against it.
