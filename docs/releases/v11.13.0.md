# EchoSpeak 11.13.0 — A focused inbox for parallel coding

Echo Code gains a flat left inbox, timed snoozing, bulk triage, native background tasks and prompt/image stashes. Optional scoped MCP connects outside tools to approved Code projects and persistent Agents; usage and local diagnostics show measured data.

> **Status:** [PR #114](https://github.com/Ty0x7/EchoSpeak/pull/114) is open and targets `claude/v11.12`, stacked on PR #113. Local EXE/MSI were produced; updater signing requires the existing key password locally. Not merged or published as a GitHub release. Installed-app acceptance remains the owner's check; the continuation below records limited live Codex success and the observed Claude weekly limit.

## Workflow

**Objective → Research → Environment → Verification → Adaptation → Completion**

The implementation starts with Echo's existing runtime, approval, queue, worktree
and verification owners. T3 research and the supplied screenshot guide interaction
changes; they do not replace those owners. Verification distinguishes scripted
models, component previews, packaged checks and real owner/device acceptance.

## What changes

- **The left Code inbox:** project-labeled flat rows, runtime marks, honest branch
  or folder context, Input/Review status and optional collapsed Working shelf.
  Snoozed and Settled sit below the active list.
- **Inbox actions:** timed snooze, wake, settle, Ctrl/Cmd-click and visible Shift
  range selection, per-item bulk results and activity-bound stale-action refusal.
- **Prompt continuity:** native Ctrl/Cmd+Enter sends background work through the
  existing query/queue. Ctrl/Cmd+S stashes prompts and bounded project images.
- **PR cleanup:** explicitly link a PR; only unchanged, clean, idle review activity
  auto-settles after GitHub confirms it merged. No merge action is added.
- **MCP access:** separate hashed, expiring, revocable project/agent grants;
  read only by default; optional control through existing harnesses. Local stdio
  only. No hidden CLI login/launch, tool approval, policy change or remote OAuth.
- **Usage and troubleshooting:** persisted reported Codex/Claude usage, available
  account limits, local CPU/memory observations and an allowlisted triage export.
  Missing quota is unavailable. No guessed totals, automatic routing or upload.
- **Model marks:** local OpenAI/Claude assets with light/dark contrast.
- **Recovery:** external rollback finality and completed/interrupted outcomes
  survive restart without replaying the task.

Native Code remains model-first with a supported local model. Chat and persistent
Agents keep their own behavior. Vendor runtimes keep their sign-in and isolated
worktrees. Native Code shares its project folder and refuses a second background
writer there; remote/mobile access and full T3 feature parity are not included.

## Build and install locally

The local installer already exists. Run from the repository root:

```powershell
& .\release\v11.13.0\runtime-reliability\EchoSpeak_11.13.0_x64-setup.exe
```

To rebuild and complete updater signing, run this in your own interactive terminal
and enter the existing signing-key password there. This does not publish:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\apps\desktop\scripts\release-windows.ps1
if ($LASTEXITCODE -ne 0) { throw 'Windows build failed' }
& .\release\v11.13.0\EchoSpeak_11.13.0_x64-setup.exe
```

The release script uses the existing updater signing key and verifies signatures.
Windows publisher signing is a separate optional configuration. PR creation does
not merge or publish these binaries. Do not use `-Publish` until explicitly asked.
