# EchoSpeak 11.0.0

Agents can now learn from their own experience. After each task, EchoSpeak checks what actually happened and keeps short lessons from work that was really checked. Before a similar task, the agent reads them. The model isn't retrained, and agents never change their own rules, permissions or tools. Whether lessons improve results is still being measured (see Validation). All 10.5.0 features carry forward.

## How agents learn

- **Every finished task is graded from what actually ran**, not from what the agent says. The grade shows how sure EchoSpeak is that it worked:
  - **Claimed**: the reply says it worked, but nothing backs it up.
  - **Ran**: tools ran and succeeded.
  - **Checked**: something was checked after the last change. A file was read back, the script was run, a test passed, or a source page was opened.
  - **Double-checked**: two different kinds of check, or two independent sources.
  - **You confirmed**: you pressed **Worked**.
- **Lessons come only from real evidence.** When no chat is running, an agent reviews a finished task with its own model and writes down up to two lessons ("when X, do Y" or "avoid Z"). It does this for failures, checked successes and anything you rated. A success nobody checked teaches nothing.
- **Every lesson starts unproven.** It becomes **proven** after it helps in 3 or more checked tasks (75% or better). It's **retired** if tasks keep failing with it, or after a long time unused.
- **Lessons are advice.** An agent reads at most three closely related ones before a task (a loosely related lesson does more harm than good), labeled as advice that never permits anything. Your request, the agent's instructions and the safety rules always come first.
- **Track records.** Each agent builds a record by kind of task, for example "research 8/9 done". Group chats use it when deciding who does what. It comes from graded work, never from what an agent says about itself.
- **Tool reliability.** When a tool keeps failing, the agent gets a note to try another way instead of repeating it. In automatic mode, a web search provider that's failing right now is tried after the ones that work.

## Worked / Didn't work

Replies have two new buttons. **Worked** confirms the task. **Didn't work** marks it failed and lets you add a note about what went wrong. The agent reads that note when it reviews the task. Press the same button again to take it back. Your rating is the strongest evidence EchoSpeak has, and it corrects the counts behind every lesson the agent used.

## The Learning page

A new **Learning** page in the sidebar shows:

- **Waiting for your review**: lessons that no agent reads until you approve them (see below). **Approve** or **Reject** each one.
- **Agents**: each agent's track record, what it's good at and struggles with, and a switch to **pause** learning for that agent.
- **Lessons**: what each one says, which tasks it came from, how often it helped or failed, and its full history. You can **Mark proven**, **Retire**, **Restore**, **Edit**, **Delete**, or **Undo** any change, including a deletion.
- **Recent tasks**: each task's grade and why it got it.
- **Reliability**: how tools and search providers have been doing lately.

## Safety

- **Learning can't loosen anything.** It writes short advice and statistics in its own file. It never changes permissions, approvals, tools, settings, tests or code.
- **Lessons are screened in code before they're kept.** A lesson is refused if it:
  - is about permissions, approvals, safety rules or secrets;
  - would skip or weaken tests and checks;
  - contains a link, a stored key or something that reads like a planted instruction.

  Your own edits follow the same rules.
- **Some lessons wait for you.** A lesson goes to **Waiting for your review** when it was learned from a task that:
  - read web pages, email or other outside content;
  - changed tests or EchoSpeak's own files;
  - is about sending things for you.
- **Editing the checks is noticed.** When an agent changes a test, a CI file or EchoSpeak's settings, later "checks" in that task don't count. Anything learned from it goes to your review.
- **Only your own requests teach.** People reaching Echo through Discord, Telegram, Twitch or Twitter, and A2A calls, never do. Their chats also never see lessons.
- **A failed model call teaches nothing**, for example a missing key or a server that's down. It doesn't count against the agent either.

## Settings

**Settings › General › Learning from experience**:

| Setting | Default | What it does |
| --- | --- | --- |
| Learn from experience | On | Off: agents don't record new experience or read lessons. What they already learned is kept. |
| Reviews per day | 30 | Background reviews per day, across all agents. Each is one short call to the agent's own model, made only when no chat is running. |
| Lessons per task | 3 | How many lessons an agent reads before a task. |

## Requirements

- **New data**: `learning/experience.db` in your data folder. Deleting that file resets learning without touching chats, memory or settings. There's no other migration.
- **Cost**: reviews use the agent's own model. With a cloud model, each review is one small paid request, bounded by Reviews per day. Set it to "None" to grade tasks without reviews.

## Validation

Automated checks:

- Backend: 56 tests for grading, lessons, feedback, review, the API and attacks. The existing agent and search suites pass with learning on and off.
- Web: type checks and unit tests.

Browser walkthrough against a scratch backend:

- the Learning page;
- approve and undo;
- a refused edit;
- Worked / Didn't work with a note;
- the settings switch.

Not yet measured: whether lessons improve results with a real model. `apps/backend/scripts/eval_learning.py` runs that comparison (learning on, off, and a same-size control on held-out tasks). It needs a live model and should be run before publishing.
