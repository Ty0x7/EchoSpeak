# EchoSpeak 11.11.3 — A search engine that reads the right source

> **Status:** source release on `claude/research-engine`, built on 11.11.2. The owner builds, installs, tests and publishes it.

EchoSpeak's search and research engine was rebuilt: links you give are read straight away, searches reach the search service as written, results are ranked by relevance instead of arrival order, GitHub and package sites are read through their official APIs, and pages that fail or don't answer are skipped for better ones.

## Links you give are read, properly

- **Paste a link and Chat reads it before answering.** It doesn't wait for the model to notice it. Small models used to search instead and miss it.
- **GitHub links are read through GitHub's API:** pull requests, issues, releases, commits, a repository and files. You get each pull request's title, state, date and link instead of the page's menus. PyPI, npm and Reddit work the same way.
- **When an API can't answer** (rate limit or not found), Chat reads the page itself and says so.

## Searches that find the right thing

- **Searches go out as written.** An old clean-up step was rewriting them: "python 3.14 release notes" was sent as "14 release notes", "site:github.com" lost its site, and a question about the 2026 World Cup final became one about today's matches. 12 of 20 typical searches were affected.
- **Results are ranked:**
  - by how well they match
  - whether they're the project's own site or repository
  - whether they're release notes or changelogs when you ask what's new
  - how recent they are

  Duplicates under different tracking links count once. On our test set, the best result is now first every time (it was first in 1 of 8 cases).
- **Only results that mention your question are opened.** If a page fails, needs a sign-in, is blocked, needs JavaScript or is off-topic, the next good result is read instead. The reason for each skip is recorded.

## Answers grounded in what was actually read

- **Every page is graded.** Did it load properly, does it cover the question, and how old is it? A page that loaded isn't automatically evidence.
- **Source chips under an answer show only pages that were read and could support it.** Raw search results no longer appear as sources.
- **If an answer cites a page that couldn't support it** (a failed, blocked or unrelated page), Chat is asked once to fix the citation.

## Verification

- **Focused tests use real tools, the real Chat loop and real ranking,** with recorded-shape search results, API responses and pages. They cover:
  - the exact pull-request question
  - the same question without the link
  - package release information
  - a rate-limited API falling back to the page
  - irrelevant and duplicate results
  - failed, blocked and empty pages
  - a search service outage
  - Private mode blocking API requests too
  - conflicting sources
  - small-model budgets
- **The existing search, browsing, privacy and loop tests** for these parts pass.
