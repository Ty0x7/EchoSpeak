# EchoSpeak 11.11.7 — Learning that has to earn its place

> **Status:** source release on `claude/learning-research`, built on 11.11.6. The owner builds, installs, tests and publishes it.

A research audit of 11.11.6's learning against ReasoningBank, ACE, Reflexion, Letta, LangMem, Claude Code, Codex, SkillsBench and the MINJA memory-poisoning attack. It's still automatic. It's now harder to fool, cheaper on small models, and measurable as learning on vs off.

## Harder to fool

- **One web page can't plant a lesson.** Something learned while reading the web is only used after work in a different conversation teaches the same thing. You don't have to approve it, and it still can't spread to other agents.
- **"Thanks, that worked" isn't proof.** Echo notes it, but only checks, or your Worked button, count as a verified success. "That's wrong" still counts, but only at the start of your message, and only for the reply you're answering.
- **Shared lessons are tested fairly.** When a lesson proven in one agent's work is offered to another, it's sometimes held back at random. Then its effect there is measured, not assumed.
- **Lessons only get credit for their kind of work.** A coding lesson isn't credited or blamed for a research answer.

## Lighter and smarter

- **No lessons for small talk,** and a size limit for the rest: about a third less room on small local models.
- **Better matching** when the local embedding model is installed: a lesson can match by meaning, not just shared words.
- **Fewer wasted reviews:**
  - The most informative experiences are reviewed first, even when many routine ones are waiting.
  - Routine successes a lesson already covers are skipped.
  - Lessons that say the same thing are merged, without a model call.

## Measurable

- **Learning on vs control.** Setting learning to *control* puts same-size unrelated notes where lessons go, and those runs are now recorded. You can compare on vs off for each model and environment: verified completion, false success, recovery, and cost. The plan is in the [report](../research/learning-research.md#4-evaluation-plan-for-the-owner).

## Verification

- **New: `tests/test_learning_research.py` (10 tests),** one or more per confirmed weakness.
- **The existing tests for the changed learning, runtime and Chat code pass (232).** A few 11.11.6 expectations were updated deliberately for the new rules.
- **Web:** the Learning diagnostics tests and the typecheck pass.
