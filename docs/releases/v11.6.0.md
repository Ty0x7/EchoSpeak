# EchoSpeak 11.6.0

Echo can now connect to apps it couldn't use before, and teams keep working until the job is done.

## What's new

- **Echo finds a way into new apps.** Ask for help with Blender, Photoshop, Premiere Pro, OBS, Figma, Stripe, GitHub, KiCad, Godot, a reverse-engineering toolkit (REA) and more. Echo looks through its setup guides (21 apps across 16 kinds of work) and the official MCP registry. It then explains what an option needs and what to watch out for, and suggests it to you.
- **You approve every connection.** Suggestions wait in Settings › Advanced › Connections & skills, under MCP servers. The card shows what will run (with its version locked), who made it, the steps inside the app, and fields for any keys. Keys are typed there and stored encrypted, never in the chat. Echo can't install or approve anything itself.
- **Echo checks that it works.** After you approve, Echo can see whether a connection is running, what went wrong if it isn't (not installed, app not open, first start still downloading, key refused) and how to fix it. It confirms with a read-only call.
- **Big apps don't crowd the chat.** When connected apps bring many tools, Echo loads only the ones a task needs.
- **Group work runs until it's done.** Teams no longer stop at a token budget, and work that keeps making progress isn't cut off at the round limit. A team that is stuck (no progress two rounds in a row, or repeating itself) still stops and says why, with a Continue button.

## Fixes

- Token use in group jobs now counts what each step adds. It used to count the whole conversation again at every step, so a build showed hundreds of thousands of tokens "used" after a few files.
- MCP servers that need start-up arguments from the registry now start correctly.
- Results that servers send twice (as text and as structured data) reach the model once.
- An MCP server's tool labels are now part of its approval, so changing them needs your OK again. Existing approvals carry over.

## Requirements

Same as 11.5.1. Each connection lists its own needs (often Node.js or uv, and the app itself). Notion, Linear and Jira's official servers need browser sign-in, which isn't supported yet.

## Validation

- Backend tests, including new suites for connections and an end-to-end approval of a real local MCP server.
- Frontend type checks and unit tests.
- Live searches of the official MCP registry.
