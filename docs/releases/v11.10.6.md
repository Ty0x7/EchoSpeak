# EchoSpeak 11.10.6

This update adds an IDE-style workbench around the existing Chat and Echo Code surfaces, using the owner's nine annotated T3 screenshots and inspected pinned T3 source as design references. The application keeps its own React/Tauri/FastAPI architecture, runtime identities, project trust and permissions.

## Workspace UI

- Three controls beside the native window buttons open workspace details, toggle the bottom terminal and toggle the right sidebar. Existing minimize, maximize/restore, close and drag behavior remain in use.
- Details show the selected computer/project or agent worktree, original runtime, branch and commit. Actions open the folder/file in VS Code, attach a project folder, save/run a named project script, inspect changes and open PRs or usage.
- The right panel has closable tabs and a surface chooser for Files, Browser, Terminal, Changes, Pull requests, Linked pull requests, Device, Research, Activity and Usage. It retains resize/expand behavior and becomes an overlay in narrow windows.
- Files expand as a lazy tree with text preview tabs and Open in VS Code. Existing private/generated/link restrictions remain. Search filters the visible expanded folders; this is not a recursive repository index.
- Native conversations retain Echo's existing Research/Activity/Artifact/Screen components. External sessions show only their original harness's reported tool/research activity. Resource browsing does not expose an unrelated chat's context.
- Chat and native Code welcome text, looping captions and composer are centered in the remaining content column. The dock changes the available space rather than pushing the welcome below it. Compact title sizing and bounded composer widths retain a one-row initial input with separate Chat/Code wording.
- The follow-up new Chat adjustment reserves Code's lower checkout/status space and matches its title/caption spacing. At 1354×801 and 1400×960, the Chat and unchanged Code heading/input tops differ by under one pixel. Existing message conversations keep their normal input dock.

## Coding composer and model picker

Echo, Codex, Claude and ACP keep the same centered welcome and one-line draft input even without a project, account or connection. Switching agents preserves the unsent draft. Sending stays disabled until the selected runtime's existing project/auth/trust conditions allow it; choosing a model or agent never sends a task.

The model popover reuses Chat's connected-model browser for Echo, with a compact logo rail for the four harnesses. The trigger shows the chosen/reported model rather than only an agent name. Native model changes are held locally until a coding session is explicitly created, then bound only to that new session using its current binding revision. An unrelated Chat session is not switched.

Codex shows its original `model/list` catalog, advertised default, thread model and explicit turn selection. Claude shows the model reported by SDK messages and permits an explicit model ID for its separate API account; it does not fabricate an available-model catalog. ACP displays optional agent-reported model state while its own agent manages model selection. Missing information says not reported/needs connection rather than naming a model that was never negotiated.

Connection setup, isolated-session selection, sign-in and original approval controls are in a bounded Connection & session popover. Pending tool approvals reveal it. Original harness text streams into the main coding conversation above the same draft input. Rollback, project/worktree binding and once-only approvals retain their original supervisor boundaries.

## Real terminal and Git actions

The Windows terminal uses pinned **pywinpty 3.1.0 / ConPTY**, with **xterm 6.0.0** and its pinned fit addon. It is an interactive PowerShell session with input, Unicode, resize, multiple tabs, split panes, scrollback, explicit stop/close, and movement between the bottom drawer and the right surface. Hiding it leaves it running. Input/output uses the existing authenticated WebSocket bridge, with origin validation, bounded frames and paced input; typing does not consume the HTTP mutation budget. PowerShell profiles and project setup scripts are not automatically executed. Shell process lifetime belongs to the existing owned-worker Job Object and Stop everything/privacy/shutdown controls.

Workbench paths are resolved server-side from the project ID and optional external-agent session ID. A selected managed session uses its isolated worktree, never an implicit fallback to the source checkout. Manual terminal groups borrow that worktree's writer lease while the agent is stopped. Reconnecting or rolling back the agent is blocked until its terminals close. Read-only views do not borrow or release another writer's lease.

Changes shows bounded tracked diffs, safe tracked/untracked names and selected-file commit controls. A Git action requires a separate review and confirmation, with workspace, HEAD, branch and selected paths. A short-lived review fingerprint is checked again after acquiring the workspace writer lock. Commits stage only selected paths and preserve unrelated staged content; known stored credentials are refused. Branch creation/switch requires a clean source checkout. Agent worktrees remain detached. Push targets the reviewed branch on an explicit GitHub origin without embedded credentials. No force push, merge, reset, automatic push or project hook execution is added.

GitHub PRs use the owner's installed/authenticated GitHub CLI. Missing CLI/auth, unsupported remotes, unknown limits and unavailable data produce explicit unavailable/error states. Linked PRs match the checkout's current branch. A detached agent worktree has no implied branch association. No GitHub token or account is copied into Echo's model settings.

## Preview, usage and device scope

The Browser surface embeds only an explicitly entered loopback dev-server URL on a different port from Echo's API, in an opaque sandbox with no same-origin, native bridge, popup or top-navigation grant. External HTTP(S) addresses open in the user's browser. Loading a preview requires Standard mode; the view clears when its privacy-status poll observes Private/Offline. Dev servers and external browsers manage their own networking, so this is not an OS network firewall or a fully featured remote browser.

Usage displays Codex-reported account windows and available Claude SDK API-usage events. Unknown values are not rendered as zero remaining; no Claude subscription quota is fabricated. Device identifies the current workspace host and points back to Echo's existing permission-controlled Screen observations. It does not claim a new mobile emulator, remote device session or screen-capture permission.

## Verification and release status

### Startup repair after the first installer

The owner reported that the first 11.10.6 installation did not open. Its backend was healthy, but the eagerly imported xterm 6 module tried to assign a namespace `toString` over the inherited read-only property from Tauri's frozen `Object.prototype`. Module evaluation failed before React could reveal the initially hidden window. The original browser fixtures omitted that production protection and missed this failure.

The Vite build now adapts that single namespace assignment to an explicit own-property definition. The pinned upstream files stay unchanged; Tauri's prototype protection, CSP and native permissions remain enabled. An unexpected upstream layout fails the build for review. A desktop startup error boundary also reveals Retry/Open logs/Close controls if the lazy desktop bundle fails to load.

The failure was reproduced before the fix. The corrected production assets pass both frozen-prototype startup and an intentionally missing-bundle recovery check (`apps/desktop/scripts/check-startup-browser.cjs`, using an existing Playwright/browser installation). The expanded workbench browser checks, including terminal construction, disconnected agents, model selection and main conversation output, also pass with the exact frozen Object prototype. TypeScript and **192 frontend tests in 40 files** pass. The 16 desktop contracts retain an explicit prototype-protection requirement.

The installed desktop binary was backed up and repaired in place, keeping the backend and app data. The real Windows/WebView2 app was observed rendering Chat, its sidebar, composer and titlebar controls. Launching it again retained one visible window and one owned backend. This verifies installed startup, not live model inference, account entitlement or every workbench action. A fresh installer build contains the same repair; earlier local 11.10.6 installer hashes are historical, not the repaired artifacts.

The [verification record](../research/echo-code-verification.json) retains the original workbench results as history and records the latest follow-up separately: **107 passing backend tests**, TypeScript plus **192 frontend tests across 40 files**, **16 desktop contracts**, a production web build, **21 protected real-component browser checks**, frozen-prototype startup/missing-bundle recovery, and six report layouts. Tests cover real temporary Git operations and ConPTY processes, runtime-reported model metadata/redaction, repeated ACP turns, selected-model routing, main transcript visibility and native binding isolation. UI screenshots use deterministic project/account/output fixtures. They are not live-provider or account-entitlement acceptance.

Local Windows builds produced the **11.10.6 EXE and MSI**, with original and repaired package hashes separated in the verification record. Both are unsigned for Windows publisher and updater use. The packaged backend's actual ConPTY start/input/output/resize, filtered API-key environment and PowerShell child cleanup smoke check passed. All ten version fields across eight files agree on 11.10.6. The installed desktop was subsequently repaired and its startup observed as described above; no public release was published. The updater signing key still requires its owner's local password for the normal release flow. Do not reuse old updater signatures.

## Local build and test

From PowerShell in the repository root:

```powershell
git switch codex/echo-code-workbench
git pull --ff-only
npm --prefix .\apps\web ci
npm --prefix .\apps\desktop ci
& .\apps\backend\.venv\Scripts\python.exe -m pip install --require-hashes -r .\apps\backend\requirements.lock.txt
& .\apps\backend\.venv\Scripts\python.exe -m pip install --no-deps --require-hashes -r .\apps\backend\requirements-code-runtime.txt
& .\apps\backend\.venv\Scripts\python.exe -m pip check
cd .\apps\desktop
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/release-windows.ps1
```

Enter the signing-key password locally. After that build succeeds:

```powershell
Start-Process "..\..\release\v11.10.6\EchoSpeak_11.10.6_x64-setup.exe" -Wait
```

Test the three controls, native Chat/Code centering with both docks, files/tabs, real terminal input/resize/split/Ctrl+C/close, a harmless project script, selected-file commit/branch behavior in a disposable repository, Git review rejection after a newer edit, native/external activity isolation and Stop everything/Private/Offline cleanup. Real PR/usage/account flows and installed WebView2/VS Code/preview behavior require owner acceptance. Publication remains a separate explicit step after the tested source is merged and release artifacts are verified.
