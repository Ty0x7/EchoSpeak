# EchoSpeak 10.x: what changed

This is a history of the application's 10.x updates, checked against the Git commits and release notes. The repository documents 10.0.0, 10.0.1, 10.0.2, 10.0.3, 10.1.0, 10.2.0, 10.3.0 and 10.3.1, followed by this 10.3.2 change. Website-only commits are described separately; they do not add capabilities to the installed app.

## 10.0.0 — the shared agent foundation

Introduced the lean tool loop across chat, voice, routines and channels. Instead of separate fixed pipelines, a model repeatedly calls tools and receives their outcomes while working on a request. Echo, Jarvis and Glados gained individual messages, handoffs and group behavior, with bounded execution and reasons when work stops.

Added local Whisper voice-model setup, the Hey Echo wake word, past-chat search, chat summaries and task-context compression. Native file reading/editing/search and background process tools support project work. Terminal Auto uses Docker when available, otherwise the host; sandbox internet, risky actions and permissions remain controlled.

Desktop startup gained an immediate splash, backend readiness/progress and a packaged background backend. Signed in-app updates, agent status/Stop controls, reorganized settings, and resizable sidebar areas became part of the desktop experience. State moved toward SQLite with message full-text search and legacy-data import. Discord, Telegram, Twitch and Twitter use the common agent path with restricted tools for non-owner callers.

Initial reductions split parts of the large frontend and removed portions of the old runtime/settings path. This was not the end of the legacy cleanup; 10.2 removed what remained.

Evidence: `81af91a` (10.0.0 release documentation) and preceding `echospeak-10` feature commits; `docs/releases/v10.0.0.md`.

## 10.0.1 — richer answers and Artifacts

Added data-backed answer presentations for weather, stocks, shopping, videos/images, sports and sources. Replies gained copyable highlighted code, sortable/copyable tables, diagrams, math, timelines, comparisons, statistics and maps. ESPN sports lookup needs no user API key.

Artifacts became versioned outputs in a side panel: apps, documents, code and diagrams can be opened, copied, downloaded, restored and revised, with an Artifacts library page. The sidebar gained pinned navigation and adjustable list sections. Echo's default personality became friendlier, while user-edited personalities were preserved. The Echo face became the app icon. External links open in the browser, and remote image loading uses size/time/public-address limits.

Evidence: `020c879` (version/release notes) and earlier visual-response/sidebar commits; `docs/releases/v10.0.1.md`.

## 10.0.2 — proper sidebar pages

Group chats, Projects, Artifacts and Routines moved into the main content area with a close/escape path back to chat. The right panel gained Artifact and Activity tabs, resize persistence and room-preserving layout. Sports cards gained logos, records, live status, local times and venue information. New installations start with a predictable sidebar layout.

Evidence: `22db379`, `aa07d87`, `5a2e5f2`, `a2d1072`; `docs/releases/v10.0.2.md`.

## 10.0.3 — local models on a fresh PC

Improved automatic LM Studio/Ollama detection and correct provider ports. Model pickers now use the selected app's models rather than carrying over the previous provider's model/address. Settings and chat bindings stay aligned while deliberately customized chat bindings are preserved. Added clearer offline guidance and removed a developer-specific default model name.

Evidence: `0ada0ef`; `docs/releases/v10.0.3.md`. There is release documentation and a version commit for this patch even though it is not among the current v10 tags.

## 10.1.0 — teams that actually work

Replaced Discussion with Work together: a shared plan, assigned tasks, real tool execution, progress tracking, result checks and continuation when work is missing. Group budgets became 15/30/60 turns, with clear done/stopped outcomes.

Soul and memory writes gained verification and read-back. Unverified save/send/remember claims are challenged rather than treated as completed work. Terminal commands can outlive their timeout, development servers start without blocking, and interactive commands receive non-interactive guidance. Task-specific recall, past-conversation retrieval and periodic progress reminders improved continuity. Tools were trimmed by agent role. Chat follows new output only when the reader is at the bottom. Dependency patches addressed reported frontend vulnerabilities.

Evidence: `2b9efe3`, `5990aaf`, `0ac3ff5`, `9dd36a6`, `9032761`, `ca95183`, `8264f13`, `807913e`; `docs/releases/v10.1.0.md`.

## 10.2.0 — smaller application and security cleanup

Removed the retired specialist runtime/pipeline, execution graph, task-run machinery, old router/mode controller, obsolete routes and their tests. `core.py` now retains the application/services object; active execution goes through the lean runtime. The API server became setup/middleware plus area-specific routers. Dashboard work was extracted into timeline, composer, provider, voice and history modules, and dead event handling/write-only state was removed.

Deleted the stale Go TUI and terminal onboarding wizard and consolidated current documentation into a guide, architecture and roadmap, with older material archived. Removed PyTorch/sentence-transformers from the default embedding path. Local document/memory embeddings use an optional ONNX model download, with model-server embeddings also supported. Agents gained scoped document search, and disposable indexes rebuild when embedding dimensions change.

Security work replaced the arithmetic eval path, hardened terminal authorization after external content, preserved host authentication authority, restricted secret inheritance in child processes, prevented provider-detection GET requests from changing settings, used constant-time admin checks, redacted tool-output secrets and improved image/approval handling. Packaging excludes the optional MCP CLI that caused the missing-typer build failure.

Evidence: `7faa767`, `d344c65`, `491623b`, `a42db3d`, `ee23549`, `dbb14ff`, `5a80d7c`, `1c1a70e`, `5e4fd4a`; `docs/releases/v10.2.0.md`.

## 10.3.0 — Creations, research tools and guided setup

Added image/video generation tools and job/asset storage. Cloud adapters cover Gemini images, Google Veo and MiniMax video; the local path uses ComfyUI. Results appear in chat and in the Creations library, with download, rename, archive and links back to the originating conversation. Cloud generation follows the existing approval path. Optional Windows/NVIDIA local setup manages an isolated ComfyUI runtime and model downloads; other hardware can connect an existing compatible installation. Large models are not bundled into the installer.

Search gained Tavily alongside existing DuckDuckGo, Brave and SearXNG support. Page retrieval gained main-content extraction, useful links and PDF text. A chat-scoped SQLite research notebook retains sources, passages and working notes for seven days separately from personal memory. The model can list/search/read/update it through a tool. This is backend research context, not a dedicated visible notebook page.

Added a resumable first-run checklist that reuses model/search/sandbox/voice/creation settings, supports optional steps and can be reopened later.

Evidence: `15710a4` / PR #30; `docs/releases/v10.3.0.md` and `docs/research/10.3-capabilities.md`.

## 10.3.1 — cloud provider connections

Improved OpenAI, Gemini, Claude and Grok credentials and model switching. Settings loads live provider model catalogs, including pagination where needed, supports refresh and preserves custom/saved model IDs. API keys use the existing credential broker and are masked on read.

Claude uses native Messages streaming/tool calls; Grok uses its compatible API; OpenAI reasoning-model request parameters are handled correctly. Gemini Live uses the native WebSocket protocol with text input, output transcription and tool continuation. This does not add native Gemini Live microphone/audio playback. Catalog visibility does not guarantee that an account can invoke a model. Errors provide more specific key/access/quota/model guidance, and settings commits are serialized.

Evidence: `7ae73ad` / PR #32; `docs/releases/v10.3.1.md`. Offline provider validation passed; paid accounts require live user testing.

## 10.3.2 — chat continuity and consistent presentation

Each chat now owns its live reducer state and event queue. Navigation no longer discards hidden stream frames or clears another chat's live transcript. Completed hidden replies are stored in their owning chat's cached timeline. Explicit cancellation remains chat-scoped.

Fixed markdown data-table layout collisions: full-width native tables, padded cells, readable minimum column widths and internal horizontal scrolling at narrow sizes. Sorting and copy actions remain. The other widget types were not redesigned.

Creations now uses the same page-card, empty/loading-state, typography and control styling as the other sidebar pages while preserving its media/library actions.

Evidence: this release; `docs/releases/v10.3.2.md`. Controlled browser streams verified concurrent chats, return during a run, page navigation and hidden completion. This keeps work running while navigating within the open application; it does not promise execution after closing it.

## Website changes during 10.x

Built the public website and GitHub Pages publishing, added docs and app-style demos, then refined motion, layout and responsiveness. Recent polish centered Echo, made the design monochrome, replaced decorative creation previews with photographic sample media, and simplified the hero. The latest requested cleanup removed the hero circles/floating labels, Artifacts demo, research showcase and motion toggle. Meet Creations now uses the second sample image at its natural proportions, without thumbnails, cloud/local controls or a footnote underneath.

These are marketing changes. Removing a website section did not delete Artifacts or the research tools from the application.

Evidence: `6513ea7` and website commits; PRs #29, #31, #33 (`c138c64`) and #34 (`d472c91`).

The retired pipeline/TUIs were actual deletions. Optional model/dependency changes reduce what must ship by default, but a signed installer-size comparison has not been measured here.

## How EchoSpeak is different now

- One main agent/tool runtime replaces multiple retired execution paths.
- Projects, agents, groups, routines, Artifacts and Creations share the app's navigation and permission systems.
- Teams can plan, execute, check and continue work; successful-sounding text is not the only completion signal.
- Local models remain supported, while four major cloud providers have dynamic selection and credential handling.
- Creation media has a durable library; research evidence has temporary chat-specific storage.
- Setup guides users through the existing configuration instead of creating a separate configuration system.
- Large optional models are downloaded deliberately, with PyTorch removed from the default embedding path.
- Chat navigation now keeps each active transcript and request separate, with table and page presentation cleaned up.

## Limits that remain

There is no dedicated research-notebook frontend. Native Gemini Live microphone/audio playback was not added. Live cloud access, billing and local GPU compatibility depend on the user's services and hardware. Installer-size reduction is a design/dependency change, not a measured promise of a specific number of megabytes. Windows signing/build and real provider testing are still required for release distribution. This history describes implemented paths and documented updates; it is not a claim that every capability has been validated end to end on every machine.
