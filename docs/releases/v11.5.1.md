# EchoSpeak 11.5.1

A security release from a full audit of EchoSpeak's code. Nothing looks different; agents just can't be talked into as much. Everything from 11.5.0 carries forward.

## What's fixed

- **Commands after reading the web always ask first.** When the terminal runs directly on your PC, any command an agent wants to run after reading a web page, email or other outside content now waits for your OK. Before, a page could steer an agent into a command that wasn't on the risky list, such as sending a file somewhere, and it ran without asking.
- **More risky commands ask first.** Downloads and uploads (Invoke-RestMethod, certutil, bitsadmin, scp, ssh), overwriting or moving files (Set-Content, Out-File, Move-Item, mv, ren, ri), encoded PowerShell and Python file deletion now ask before they run on your PC.
- **Your keys stay with EchoSpeak.** Programs an agent starts (MCP servers, package installs, dev servers) no longer see EchoSpeak's search, Discord, Telegram, email, Notion, Home Assistant, Twitch, Twitter, Runway or GitHub keys. Keys you set for one MCP server on purpose still reach it.
- **Agents can't touch EchoSpeak's own settings.** File tools can't read or change EchoSpeak's data folder, where its settings and its approvals for skills and MCP servers live, so an agent can't approve itself.
- **Memory files can't be swapped out.** EchoSpeak remembers a fingerprint of its memory and document search files and won't load one that changed outside the app. Memory rebuilds itself instead.
- **Stronger protection against pages pretending to be EchoSpeak.** A page can no longer fake the end of "this is outside content" with a differently written tag.
- **File access stays inside your project.** Opening a project no longer also allows its parent folder.
- **Memory clean-up stays out of the way.** It no longer holds memory while it compares, so chatting during a clean-up isn't slowed down.
- **Math in answers uses the patched KaTeX** everywhere in the app.

## Requirements

Same as 11.5.0. No data migration. Memory and document search files from earlier releases are trusted once and protected from then on.

## Validation

- Backend tests, including a new hardening suite for every fix above.
- Frontend type checks, unit tests and the production build; npm audit reports no issues.
- 16 desktop contract tests.
