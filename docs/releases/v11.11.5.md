# EchoSpeak 11.11.5 — Verified engineering: measured progress, honest completion

> **Status:** source release on `claude/verified-engineering`, built on 11.11.4. The owner builds, installs, tests and publishes it.

When Echo works on code in Agents or Code, it now measures its progress instead of guessing at it. It runs the check, sees exactly what failed and whether it's getting closer, and knows when to change approach or stop. It also tells you honestly whether the work is verified. Learning now credits and blames only what the approach actually caused.

## Echo checks its own work, properly

- **Every test, build or benchmark it runs is measured.** Echo sees:
  - how many tests passed and failed, which ones failed, and the first error
  - whether that's better or worse than its best attempt so far
- **It knows when it's stuck.** After three tries that don't improve anything, it's told to try a different idea or tell you what's blocking it, instead of retrying the same fix. If a change makes things worse, it's told how far back the best version was.
- **It can't fake a pass.** Editing the tests after they failed doesn't count as verification, unless you asked for test changes. Saying "all tests pass" over a red run gets sent back once with the evidence.
- **It can set a goal before it starts.** For bigger work, Echo records the acceptance criteria and the command that checks them, and optionally a number to improve ("under 100 ms"). It then measures every attempt against them.
- **Missing setup is called what it is.** A missing package or program is reported as a setup problem with what to install, not as a bug in the code.

## An honest status under every engineering answer

A line under the answer says what the evidence shows:

- **Verified:** the task's own check passes.
- **Checks pass:** the checks after the last change pass.
- **Partly verified,** with what's still missing.
- **Not verified,** and why.
- **Blocked,** and by what.

The best result so far is always mentioned, even if the last attempt was worse. Interrupted work picks up from what was measured.

## Learning that blames the right thing

- **A broken setup, a refused action or an outage no longer counts against a lesson or an agent.** Before, a broken environment could retire a good lesson.
- **Your "Didn't work" is understood:**
  - On a task whose checks passed, it marks that the checks missed something, for example "the file was generated, but it doesn't open in Excel".
  - "You misunderstood" isn't held against Echo's approach.
- **The Learning page shows why each task turned out the way it did.**
