# EchoSpeak 11.7.1

Echo can inspect the screenshots it takes, show them in chat, and use bounded computer controls through the existing harness.

## What's new

* **Actual screenshot pixels.** Monitor and visible-window captures reach the current chat model instead of returning only a filename. Vision models use the existing cloud/local adapters; images are also forwarded during Gemini Live tool continuations.
* **Visible in chat.** Each screenshot has its own preview. Open the original or save it through the shared right panel alongside artifacts, activity and research.
* **Reopen and zoom.** View an observation by ID or read an allowed project image. Crops use original image pixels and are for inspection, without implicitly changing desktop coordinates.
* **MCP image results.** Image content from connected MCP tools becomes a chat preview and model image input. Base64 image blocks are removed from persisted tool text.
* **More computer controls.** Click, double-click, right-click, move, drag, scroll, type, shortcuts and brief key holds. Batches allow up to 12 actions and five seconds of requested hold, wait and drag duration; each ends with a new screenshot.
* **Existing safeguards.** Desktop permissions and approvals remain in force. Captures are chat-scoped, and input requires a capture from the last two minutes. Changed window or monitor bounds are rejected. Held keys and mouse buttons are released on errors and cancellation. Screen content counts as untrusted input for action approvals.
* **Clearer readiness.** System check reports capture/input dependencies and whether desktop control is disabled. Explicitly text-only model profiles receive a clear image-capability error. Smart model choice retains the selected model for recognized visual tasks and chats carrying recent observations, since its rankings do not verify vision support.

## Data and requirements

Temporary observations are separate from personal memory and Creations. Originals are retained for up to seven days within a 512 MB store; at most three recent observations enter model context. Older chat cards can expire. Cloud vision sends the image to the selected provider, subject to EchoSpeak's privacy controls.

Input requires Windows, system actions and desktop automation permissions, the agent's Desktop toolset, and applicable approval. Screenshots require an available capture environment. Vision depends on the chosen model. OCR requires its separate Tesseract installation.

This enables slower screenshot-and-action interactions, including compatible games. It does not add a real-time game controller or guarantee game compatibility.

## Validation

Offline checks cover image payloads, tool-loop previews, scoped storage, crop and coordinate mapping, stale observations, permission checks, and releasing input after failure or cancellation. Frontend checks cover cards and the shared panel. Real provider vision, multi-monitor DPI behavior, target applications and gameplay still need testing on the user's setup. A packaged Windows release check is still required.
