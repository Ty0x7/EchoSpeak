# EchoSpeak 10.4.0

EchoSpeak gains recoverable background chats and creation jobs, evidence linked into the shared sidebar, image editing and related versions, project continuity, a guided setup ending in a ready first chat, and stronger Windows packaging and release safeguards.

## Windows launch and updating

- Explicitly bundle LangChain's lazy modules, including the `Runnable` import that prevented the installed backend from starting. The release build runs the frozen executable's import self-check before staging it.
- Recognize permanent startup import failures and explain the missing dependency instead of repeatedly exhausting automatic recovery. Transient service crashes retain bounded recovery.
- Production desktop builds use the Windows GUI subsystem. Backend, child commands and shortcut repair run without a visible command window.
- Repair existing EchoSpeak desktop, Start Menu and taskbar shortcut targets after NSIS installation and on production launch. Preserve shortcut arguments; do not replace unrelated links or point a newer target back to an older executable.
- Add a Windows GitHub Actions build with packaged self-checks, updater-signature verification, optional publisher signing and draft release assets. Existing updater keys must be supplied as secrets; the workflow does not publish an untested installer automatically.

## Chat and creation recovery

- The backend owns a chat run independently of its HTTP reader. Disconnecting or refreshing no longer signals cancellation. Stop remains scoped to the exact request and chat.
- Record ordered output in a local two-day transport journal. Reconnect by cursor; request IDs reject a different prompt or chat and do not start the same request twice. Reloaded chats reattach to active runs. Replayed audio is suppressed.
- A backend restart preserves partial output and marks the run interrupted. It does not automatically repeat tools or restart a chat request.
- Saved Google Veo, MiniMax and ComfyUI job IDs can be polled after interruption, automatically on startup where possible or through Reconnect to existing job. Recovery never makes another generation submission. Synchronous image requests without a saved remote ID cannot be recovered this way.

## Research and projects

- Click a retained research citation to open its supporting source in the existing Artifact / Activity / Research sidebar. Links without retained evidence still open externally. Search snippets and actually read pages remain distinct.
- Edit working findings, open questions and conflicting findings; export a Markdown report. Sources and notebook notes remain temporary, scoped to the chat and separate from personal memory.
- Explicitly save working notes and up to 20 read sources to the chat's attached project. Project briefs and saved evidence are available to subsequent project chats. Saved web material is marked untrusted information, not agent instructions.

## Creation editing and setup

- Edit existing generated images through Gemini image references or a local ComfyUI image-to-image preset. Cloud editing uploads the selected references through the normal approval flow. Video editing is not added.
- Preserve original assets, verify reference hashes and chat/project scope, retain edit lineage and show related versions in Creations.
- Introduce a monochrome Echo welcome with a brief spin and step transitions, consistent with the existing app. Optional features can be configured later.
- Download and load supported starter chat models through an installed Ollama or LM Studio runtime after an explicit choice. The runtime must be running; this does not silently install a new runtime or arbitrary software.
- Verify the exact selected model's response before completing setup. A local model listing alone no longer counts as working generation. The first chat opens only after setup finishes; no greeting request is automatically sent.

## Carried forward

Includes the earlier four-provider cloud catalog/readiness work, native Gemini Live audio path, verified resumable managed local-generation downloads and GPU checks, shared right sidebar, and mobile website cleanup. Existing tools, approvals, chat history, media catalog, memory and project storage remain in place.

## Release validation

Focused checks cover disconnect/idempotency boundaries, saved remote-job polling, reference identity/scope, provider adapters, sidebar behavior and the setup-to-chat sequence. The Windows frozen backend build and its import self-check passed, including `Runnable`; recovery unit checks and shortcut fixtures passed too.

The saved Gemini selection was a display name rather than an API model ID. Google rejected the saved credential with HTTP 401 (`ACCESS_TOKEN_TYPE_UNSUPPORTED`). Successful Gemini generation still requires a valid Gemini Developer API key and a model ID available to that account; it was not confirmed by this test.

Windows release distribution still requires the final built and signed installer and clean installation/update checks. Real native microphone, GPU rendering and publisher-certificate validation remain machine-specific. Configure the existing signing key in GitHub secrets before using the new release workflow. An updater signature and an Authenticode publisher signature serve different purposes.
