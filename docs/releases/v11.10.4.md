# EchoSpeak 11.10.4

Echo Code adds a project-focused coding workspace using Echo's own harness. Chat and Code share quieter styling and searchable model/reasoning popups. Security hardening updates the build dependencies, process defaults, untrusted-input handling and updater verification.

## Echo Code and shared appearance

- Open **Echo Code**, choose an attached trusted project, and create an **Echo native** session. A task entered in the workspace arrives as a draft; choose your model and send it through the usual composer.
- Project files and coding-session history remain available from **Files & sessions**. Coding sessions keep their own surface/runtime identity and native prompt branches preserve it.
- The shared model popup supports search, provider filtering, favorites, keyboard selection and Escape. The reasoning menu follows the selected model's capabilities.
- New profiles start in dark mode. Saved dark, light and system preferences remain authoritative. Existing voice and conversation controls remain available.

## Security implementation

- Patched dependencies and a hash-pinned Python build environment, checked before packaging.
- Child-process Git bundle URI transfer disabled; npx install scripts disabled by default for MCP servers.
- Project instructions labeled separately from the owner's instructions; skill proposals after outside content require approval under the existing Rule of Two policy.
- Malformed HTML pre-processing mitigates the tested parser denial-of-service path.
- Version-bound updater signatures, release verification, dependency advisory checks and pinned CI Actions.

See the [technical security audit](../research/security-audit-2026-10-25.md) for reviewed advisories, residual interpreter risks and historical audit evidence. Prompt injection and host execution are not fully contained by these changes.

## Verification and acceptance

The original combined implementation passed 168 focused backend tests (one Windows symlink skip), 180 web tests and TypeScript, 16 desktop contract checks, four Rust tests, production/site builds, 11 fixture/browser checks and an isolated packaged-backend smoke test. Those checks were initially performed under the 11.10.3 development version; the [verification record](../research/echo-code-verification.json) records the subsequent 11.10.4 build and checks separately.

Fresh 11.10.4 preparation checks: all **10 version entries** agree; **35 Echo Code/security tests** and **16 desktop contract checks** passed. The 11.10.4 updater-signed build remains pending the owner's local signing-key password; no 11.10.4 installer or publication is claimed yet.

Manual acceptance remains the owner's: install the new build, test native coding with the chosen model, model/reasoning menus, saved appearance, ordinary Chat and permission behavior. Existing reminder/tray and Minecraft acceptance cases remain in [TESTING_GUIDE 4.2–4.10](../TESTING_GUIDE.md).

## Limits and publishing

- Echo native is the only runnable coding harness. Codex, Claude Code and ACP choices are planned integrations; no login or external runtime execution is implemented.
- Windows publisher signing is not configured. Updater signatures are separate from a Windows publisher certificate.
- This is a new release version because v11.10.3 already exists. Building prepares local release files; publishing requires the separate `-SkipBuild -Publish` step after testing.

From `apps/desktop` in PowerShell, build with `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/release-windows.ps1`. Install `release/v11.10.4/EchoSpeak_11.10.4_x64-setup.exe` from the repository root. After testing, publish with the same script and `-SkipBuild -Publish`.
