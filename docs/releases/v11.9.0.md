# EchoSpeak 11.9.0

EchoSpeak 11.9.0 combines the visual project workspace with all harness improvements originally prepared for 11.8.0, including ElevenLabs, MCP sign-in and interactive views, longer-running tools and stronger computer control. It also includes the 11.7.1 screenshot and desktop-control work. The 11.8 branch was integrated before publishing this combined release.

## Harness improvements included from 11.8

* **ElevenLabs read aloud.** Choose a voice in Settings, play a sample and use it for reply playback and supported voice conversations. Requires your ElevenLabs account/key; Private and Offline modes block the cloud service.
* **Computer control.** Compatible Claude models can use their native computer tool through EchoSpeak's checked executor. Other models keep the general controls. Desktop permission setup offers to enable the matching agent tools; bounded holds, triple-click and horizontal scrolling are included.
* **MCP sign-in, views and long tasks.** Hosted servers can use OAuth with encrypted token storage. Supported MCP Apps appear in sandboxed chat views. Long-running MCP tools report progress and support cancellation; services requiring unsupported mid-task input report that limitation.
* **Safer outside content and better diagnostics.** The optional quarantined reader reduces raw outside text reaching the acting model while keeping it untrusted. Long tool outputs remain available through read handles. Activity includes reply timing, with optional OpenTelemetry export.
* **Pinned remote agents.** Owner-approved signed Agent Cards and brokered credentials support the existing outbound A2A tool. Sending a task requires owner approval in every approval mode. Remote results remain untrusted; full recoverable multi-agent task coordination is separate future work.
* **Smaller dependency surface.** Tools, memory search and document search use EchoSpeak's own implementations. Existing 11.7 indexes convert without re-embedding. Bundled skills now use the native tool decorator, and desktop packaging excludes LangChain as well as PyTorch.
* **Release evaluation.** The Echo bench is included for owner-run real-model evaluation. No benchmark results or provider performance gains are claimed for this release.

More detail on the carried-forward work is in the [11.8 notes](v11.8.0.md).

## Project workspaces

* Open a project to browse its reports, files, conversations, saved research, artifacts, media, routines and activity in one place. Opening the workspace does not move the current chat into another project.
* Keep named Markdown or HTML reports with revisions, related files and images, source-agent details, reported checks and remaining work. Read reports, inspect original images and download results using EchoSpeak's existing rendering and shared panel.
* Echo can read the bound project's workspace and save a report through native tools. Selected screenshots from the current chat can be preserved with a report when file-write permission allows it.
* Existing project records and artifact history provide storage. No additional database, model runtime or agent scheduler is required.

## Optional sharing with coding agents

* Enable sharing on an attached project to prepare a local `.echospeak` handoff folder. Independent Codex, Claude Code and Echo work can publish structured reports into the same project workspace.
* Stable report IDs and increasing revisions prevent duplicate imports and stale overwrites. Incomplete or conflicting updates leave the last accepted report available.
* Explicitly export the project brief, saved research and bounded workspace context for other authorized agents to read. Conversations, credentials and global personal memory are not exported.
* Optional hooks can record that an agent turn ended or failed. They do not mean a task succeeded, verify tests or automatically start another agent. Agent configuration stays under the owner's control.

See the [Project Workspace guide](../PROJECT_WORKSPACE.md) for setup, report conventions and limitations.

## Computer control carried forward

* Screenshots reach vision-capable models as image inputs and appear in chat, with original-image viewing through the shared panel.
* Bounded desktop controls include clicks, typing, shortcuts, dragging, scrolling, relative mouse movement and brief simultaneous key/button holds, followed by a new capture.
* Clearer Desktop toolset and allowed-application guidance, Windows Store app resolution and saved desktop shortcuts improve app-launch recovery.
* A chat-wide screen-control approval supports continued screen-guided work. Existing privacy controls, permission checks, untrusted-content rules, capture freshness and input-release safeguards remain active.

These controls support screenshot-and-action interactions; they do not guarantee real-time game control or compatibility with every application. More detail is in the [11.7.1 notes](v11.7.1.md).

## Safety and compatibility

Reports remain untrusted content. Imports check project identity, file scope, revisions and session/artifact associations. Private paths, traversal and unsafe links are rejected. HTML reports reuse the existing sandbox. Existing projects load without a migration, with sharing disabled until enabled by the owner.

Main report documents retain snapshots. Linked files and images reflect their current contents, so use versioned asset filenames when historical comparisons matter. Automatic sync runs while the project workspace is open; it is not a continuous background watcher.

Project report bookkeeping does not count as evidence that an implementation task was completed. Project artifact browsing and chat timing retain their distinct contexts inside the same right panel.

## Validation

The combined backend suite passed **1,014 tests with 13 skipped**. A separate focused integration run passed **85 tests with 1 skipped**; these are not additive totals. Frontend checks passed **149 tests**, TypeScript checking and the production web build. All **16 desktop contract tests** passed. Both the backend source self-check and a newly built PyInstaller backend's startup self-check passed. Checks used isolated disposable state and blocked real provider connections.

An isolated localhost preview with synthetic data checked desktop and mobile report rendering, file navigation, original-image viewing and overflow. No paid model calls or real external-agent sessions were used. Windows installer builds, installed-app behavior, real-provider vision, external-agent hooks and gameplay still need manual testing on the owner's setup.
