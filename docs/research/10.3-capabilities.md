# EchoSpeak 10.3: integration decisions

Repository and primary-source review, 2026-10-04. This is an extension of the lean
runtime, not a new agent framework.

## Existing systems and gaps

- `lean/runtime.py` creates a Toolbox per persona; `lean/loop.py` enforces
  approvals, streams tool cards, persists their timeline, and compacts context.
- `generation_runtime.py` already owns durable generation jobs, but every
  adapter is unavailable. Its submission authority requires retired TaskRuns.
  Keep the job contract and store; bind new work to the actual lean session and
  execution. Do not reintroduce TaskRuns.
- `media_library.py` already owns immutable assets with hashes and provenance.
  Add a library storage scope for creations without an attached Project. Keep
  existing project assets readable. Chat and Creations reference the same ID.
- `web_search_providers.py` has DDG, Brave, and SearXNG, query variants and fallback.
  The tool already accepts multiple queries, but claims Tavily support it lacks.
- `safe_web_retrieval.py` pins public DNS addresses, checks redirects and caps
  responses. Keep these protections while improving HTML extraction, adding PDF,
  retaining links and allowing cached-page pagination.
- Durable research projections in `state.py` are display history, not a searchable
  working notebook. Chat summaries and personal vector memory serve other purposes.
- There is provider auto-detection and settings for models, search, terminal,
  voice and credentials, but no durable first-launch wizard.

## Chosen boundaries

1. Native lean generation tools call provider adapters, retain one durable job,
   and attach a creation card. No MCP server is required for a built-in capability.
   Provider and model defaults remain user choices. Cloud jobs disclose upload
   and possible charges through the existing approval card. Guest callers cannot
   create or read private creations. No model-selected install commands.
2. Creations is a sidebar page below Routines. It lists images/videos across chats,
   provides preview/download, provenance, open-chat and archive/restore. Output is
   retained locally rather than depending on an expiring provider URL.
3. Start with Gemini image/Veo video and local ComfyUI; adapters must report actual
   readiness and reject unsupported options. MiniMax is a real video API, not a
   downloadable local model. Additional adapters use the same job contract.
4. Local setup uses a separate managed runtime, explicit install consent, official
   pinned artifacts, integrity checks, bounded extraction and hardware/disk checks.
   Existing ComfyUI installations can be connected without overwriting them.
   Image and video models are separate optional downloads. CPU generation is slow;
   GPU/driver compatibility and model licensing remain real prerequisites.
5. Research results retain URL/title/date/content and stable source IDs in a
   bounded, expiring, session-scoped notebook. Tools can list/search/read passages
   and record open questions. Research text remains untrusted, including after
   recall. It is never automatically added to personal memory. The existing loop
   chooses additional queries and sources; instructions require checking gaps and
   citing inspected sources without pretending that a source-count proves truth.
6. Setup is resumable and dismissible. Detect local models and dependency status;
   reuse settings controls and credential storage. Model readiness is explicit;
   optional generation, voice and sandbox setup never block entering the app.

## Primary research

- [Gemini images](https://ai.google.dev/gemini-api/docs/image-generation): native
  image output uses the content API, not the chat-completions compatibility API.
- [Veo](https://ai.google.dev/gemini-api/docs/veo?hl=en): asynchronous operations;
  poll and download results promptly. Availability depends on account and billing.
- [MiniMax video](https://platform.minimax.io/docs/api-reference/video-generation-t2v)
  and [status](https://platform.minimax.io/docs/api-reference/video-generation-query):
  cloud task submission, polling and file retrieval.
- [ComfyUI API](https://docs.comfy.org/development/comfyui-server/comms_routes):
  submit API workflows, inspect history, retrieve outputs. Interrupt is server-wide,
  so an external shared server must not be interrupted indiscriminately.
- [Portable runtime](https://docs.comfy.org/installation/comfyui_portable_windows)
  and [hardware](https://docs.comfy.org/installation/system_requirements): isolated
  Python/runtime packages; hardware-specific builds.
- [Wan 2.1 recipe](https://docs.comfy.org/tutorials/video/wan/wan-video): a native
  text-to-video path using diffusion model, text encoder and VAE; 1.3B is the
  lower-memory option. Faster/newer/larger models remain selectable separately.
- [Tavily search](https://docs.tavily.com/documentation/api-reference/endpoint/search)
  and [extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract):
  structured discovery/extraction; optional API rather than mandatory paid search.
- [Trafilatura](https://trafilatura.readthedocs.io/en/latest/usage-python.html): main
  content extraction from already-fetched HTML; do not delegate network policy.
- [Context engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents):
  structured notes and on-demand retrieval keep long investigations useful.

## Release checks

Exercise provider contracts with fixtures, job failure/cancellation/idempotency,
asset path and content validation, notebook isolation/expiry, parser and SSRF
regressions, onboarding persistence, frontend build and real chat-card rendering.
Paid provider calls and multi-GB model installs need explicit live validation;
mocked success is not evidence that a user's account or GPU can generate.
