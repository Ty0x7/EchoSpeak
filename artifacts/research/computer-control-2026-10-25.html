2 · Four causes, all in the harness

recorded as success

"Control not found." was ok

Desktop tools report failure only in their text, and none of their wording was on the failure list. The model took it as "clicked".

looking ≠ doing

vision_qa ignores its question

It's a screenshot. Asked to "click", it captured, succeeded, and said nothing about not clicking.

no explanation

A game names no buttons

Minecraft draws its menu itself; Windows sees only the title bar. The screenshot listed nothing and didn't say why.

no stall check

Every look "worked"

The repeat check skips screenshots (screens change), the animated menu changed every image, and the fail streak counts failures only.

3 · How the stall check counts

Calls that never ran (skipped after an earlier failure, refused, denied) count for nothing. Approvals are unchanged.

4 · Did it need a skill?

harness

The fix is in the tools and loop

A skill is advice the model reads; it can't stop a tool reporting a failure as success. So the loop was fixed where it broke.

bundled skill

desktop-apps-and-games

General know-how: look, one step, act, check; recovery; menus and toggles; game input. Add it in Settings › Skills.

Echo drafts

propose_skill

After something works, Echo offers to save the steps (e.g. minecraft-new-world). It's a draft until you approve it.
