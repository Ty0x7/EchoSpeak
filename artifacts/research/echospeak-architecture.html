Why “agentic” does not mean “Agents tab”

A Chat model choosing search tools is doing bounded agentic work. Code can run an engineering loop without a persistent persona. The Agents experience adds continuing identity and responsibility. These are product contracts, not different levels of model intelligence.

Session, context, model and identity

A session is durable history. The context window is what the model receives now. A model supplies inference. An agent identity supplies persistent instructions/responsibilities. Sharing execution code should not merge these states.

Better models change the scaffolding

Measure and simplify

Corrective reminders, forced planning, tool-name repair, compact prompts and repeated review calls may help one model and slow another. Test them with the exact selected model.

Keep explicit contracts

Who can write files? Which history is retained? What survives a crash? What counts as verified? These remain application responsibilities as models improve.

Anthropic's 2026 work describes model-specific resets becoming unnecessary and separates session, harness and execution environment. This supports revisiting assumptions, not removing all runtime infrastructure.

The harness at a glance

Everything outside the model is code that decides what the model sees, what it may do, and what is kept. The model chooses the next step; the harness checks and executes it.

How one message becomes multi-step work

A turn is a loop, not a single answer. Each step's results go back to the model; the turn ends only when it answers without tools, you press Stop, or the step budget runs out.

How a tool call is selected, authorised and run

Each gate is code with a fixed answer for the same inputs. Later gates can only ask or refuse; none can grant what an earlier gate removed.

Research workers under a lead

Phase 1 is deliberately narrow: few workers, read-only, bounded, and the lead stays responsible for the answer. Off by default until the bench shows a gain for your model.
