Two clients, one authority

The backend already owns runs. A detached collector journals every event, readers reattach by cursor, and controls are separate requests. The terminal is another client of that, not another engine.

One running request per conversation is enforced by the journal; a second client steers or queues. Gaps: a per-session follow stream, approval answers attributed to a client, and a generated event schema.

What transfers from the references

DeepSeek Harness

TypeScript on Cordis, ~557k lines, prerelease, unaudited.

  • Already in Echo: controls as requests, asked/decided approvals, cursor replay, crash repair.
  • Adopt: log a hash of the prompt and tool set per step; bubblewrap with honest confinement reporting.
  • Skip: Cordis, YAML layers, generated RPC.

Hermes Agent

Python, ~1.07M lines; a gateway daemon owns sessions.

  • Already in Echo: backend authority, idempotent submits.
  • Adopted: a command floor under every approval mode.
  • Adopt next: generated wire schema, byte-stable prompt prefix.
  • Skip: autonomous skill-writing forks. They are unevaluated, and SkillsBench shows self-generated skills average −1.3 points.

Echo's learning design (advisory lessons, outcome grading, randomized holdout) matches the published evidence better than either reference.
