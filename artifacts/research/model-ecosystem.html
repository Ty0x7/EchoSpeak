Concrete compatibility repairs

PROTOCOL

GPT-6 → Responses

Stateless requests, streamed text and scoped opaque state. Tools return only after a completed response. Echo still owns every execution decision.

MODEL CONTROLS

Effort reflects the family

Documented Claude output_config; Gemini 4 Argon; OpenAI xhigh/max and supported off settings. Non-thinking Coder-Next no longer inherits the Qwen3 heuristic.

CONTEXT

A known window is a bound

A configured 4K local model no longer inherits a 64K minimum. Global trim settings can reduce known windows. Output reserves and usage use the resolved budget.

Verified contract evidence: 109 passed across 6 targeted backend test files. Live model behavior remains unverified. Details and source hashes are recorded in the technical evidence file.

Content, reasoning, tool IDs, arguments and usage. Opaque provider state remains internal to the active turn.

Echo policy & Toolbox

Validate arguments, project scope, caller role, approvals, taint and Stop. Native and recovered calls share this gate.

Feedback & continuation

Return results and errors to the selected model. Trim/compact when needed. Stream visible events into the existing timeline.

The server is part of the compatibility contract

Local runtimes

LM Studio and Ollama offer compatible HTTP. llama.cpp, vLLM and SGLang require matching architecture, template, tool/reasoning parser and multimodal support. Echo’s in-process llama_cpp choice is not a lean HTTP endpoint.

Cloud hosting

Together, Fireworks, Groq, Cerebras, HF and OpenRouter have separate credentials, IDs and policies. Echo has no first-class account adapters for these. Bedrock/Vertex/Foundry add platform authentication and deployment contracts.

Memory planning: total parameters × bits ÷ 8 is only the weight floor. KV cache, projectors, buffers and parallel requests add memory. MoE active parameters are not total memory requirements.

Known gaps remain visible

  • DeepSeek/Kimi tool workflows may require reasoning_content history; parsing visible reasoning does not satisfy that requirement.
  • Grok’s newer Responses/effort path and authenticated local endpoints need further integration.
  • Provider-reported catalog limits are retained, but are not automatically applied to every runtime profile.
  • Unmeasured family defaults remain diagnostic assumptions, not negotiated capability proof. Generic audio/video/strict schema support is not inferred from a model name.

A focused owner acceptance pass

  1. One GPT-6 model: harmless read → tool result → answer; Stop mid-stream and switch models between turns.
  2. One current Claude model: low/high effort, permitted tool cycle and a denied action.
  3. Gemini Argon or supported Flash: multiple tool IDs/signatures and a recoverable error; Live separately.
  4. One familiar local Gemma/Qwen instruct model: native tool, malformed arguments and a small configured context.
  5. Private/Offline mode: remote model blocked; local work keeps project and tool restrictions.

Choose only the models you use. This is not a paid benchmark campaign or a request to download a catalog.
