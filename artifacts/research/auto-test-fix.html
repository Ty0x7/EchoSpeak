17 November 2026 · branch env-intelligence · apps/backend/scripts/auto_test_fix.py · technical record: docs/research/auto-test-fix.md

Three parties, three kinds of authority

System under test

EchoSpeak's harness running qwen3.5:9b (any --model), in disposable eval projects behind the recorder. Its output is evidence only.

Engineering agent

Claude Code or Codex today; any CLI agent with --driver command, EchoSpeak itself later. Edits one disposable worktree with scoped tools, a time and spend limit.

The loop

Deterministic Python. Runs, judges, diagnoses, gates, measures and records. Only it commits, only on a session branch, and it never pushes or merges.

Demonstration 2: Codex engineering

Found blind

Given only E1's trail, Codex wrote a failing test showing that a path like /work/echospeak-cache/… plus "release" makes EchoSpeak prefetch its own GitHub pages.

Stopped by its plan

Codex then hit its usage limit with no fix and no report.

The loop learned

An agent that doesn't finish is now driver_failed: recorded, reset, never gated.

Run it

cd apps/backend
.venv/bin/python scripts/auto_test_fix.py discover
.venv/bin/python scripts/auto_test_fix.py run --driver claude --cases D7,E1 --heldout H7,EH1 --repeat 3 --cycles 2
.venv/bin/python scripts/auto_test_fix.py status     # progress
.venv/bin/python scripts/auto_test_fix.py stop       # finish the stage, then stop
.venv/bin/python scripts/auto_test_fix.py review     # decisions, evidence, commits

--driver codex runs codex exec -s workspace-write; --driver command --driver-cmd "agent --brief {brief} --cwd {tree}" takes any agent; --driver manual writes the brief and waits for run --resume.
