Who owns what

Echo Chat · specialists

One Lean harness; personas are identity + instructions + model + toolsets. State: StateStore + ThreadManager; work in the coordination ledger. Specialists get project/session memory, not Echo’s account-wide view.

Groups

RoomStore + a request-local Job. Mentions or a routing call pick speakers; a judge decides “done”; work-together uses an owned task board.

Routines · reminders · responsibilities

RoutineManager is the only scheduler. Plain reminders never call a model. Responsibilities are reviewed in Activity, with grants frozen at the first occurrence.

Echo Code: native

A Code-surface thread on the same native route and model binding, with native tools and policy.

Echo Code: Codex · Claude Agent · ACP

The original harness in its own worktree, with its own sign-in, tools and approvals. Echo maps exact approval IDs and fails closed. No Echo memory, keys or tools cross over.

Workbench

Terminal (ConPTY), files, changes, reviewed Git/PR. The Browser tab is a local preview frame, not automation and not your accounts.

Codex · Claude Agent · ACP, checked 27 October

Claude Agent

The official SDK page says third-party products can’t offer claude.ai login without Anthropic’s approval; use API keys. Echo’s explicit-key “Claude Agent” is the supported path. Running the unmodified Claude Code CLI with your own login is a separate case. Not installed here.

Codex app-server

stdio JSON-RPC, with initialize, thread and turn calls and approval requests. Labelled experimental; thread/rollback removed (Echo doesn’t use it). Echo refuses token requests and fails closed. Not installed here.

ACP v1

initialize, session/new, session/prompt, request_permission and update; load is optional. Echo advertises no filesystem or terminal capabilities and refuses unsupported resume.
