Technical notes and resource measurements

What a larger window costs here (measured)

RTX 3060 Ti 8 GB · Ollama 0.40.16 · flash attention · q8_0 KV cache. qwen3.5:9b is hybrid: only 8 of 32 layers keep a KV cache (16 KiB per token at q8_0: 256 MiB at 16K, 1 GiB at 64K). Ollama holds ~5.6 GB of this card for the model; a bigger window moves more of the model onto the CPU.

The prompt layout fix

llama.cpp reuses the unchanged start of the previous prompt (9.4K tokens: 4.09 s → 0.31 s). EchoSpeak ended its system prompt with the time to the minute, and the system prompt comes before the tools and the whole history, so every new minute meant reprocessing all of it. The time (and git status) now ride on the current request.

How EchoSpeak stays inside 16K

History

Last 30 messages verbatim; older turns as a per-chat summary. Tool outputs aren't carried across turns, only replies.

Within a turn

Older steps summarised (≤ 200 words) and trimmed when the window fills; big outputs saved behind out-… IDs and reread with read_output.

Memory

Retrieved per request (top 8), now on the request rather than the system prompt, with memory_search and chat_search on demand.

Agent awareness, from the owner's session

Guessed IDs, corrected with facts

The model called read_output with invented IDs, then made 76 more calls. A wrong ID now gets this chat's real saved outputs (or "none").

The right tool, from the request

"look at codex and claude sessions" never reached agent_sessions. Strong, distinctive matches between a request and a hidden tool now list it up front: across 52 evaluation prompts, only the two session questions gain a tool.

Past chats found

chat_search needed every word of a descriptive query; it now ranks by shared words. "Did I mention…" now points back.

Saves that happen

An unbacked "I've saved / updated that" gets one step to call memory_save; the builder is offered it; recalled facts show their key so a change replaces them.

Cache, honestly

Recall moved to the request: reused prefix 0.85 → 0.94 and no memory breaks, but prefill stayed ~0.2–0.3 s. This Ollama build already restored earlier prompts.

"I ran out of steps (60)"

The owner's turns stopped after 6 look-up steps, not 60: the final answer call wrote the whole answer as reasoning and returned no reply. That call now runs with thinking off (6.6–7.7 s, against up to 86.5 s with thinking on), an answer written as reasoning is recovered, the note states the real limit, and the agent carries on past its limit while it is still making progress (up to 5 stretches; "Kept going" in the terminal).

Verification round: ×4 memory, a live long task, one branch

Memory and long-session cases, four trials each with qwen3.5:9b: 51/56 → 60/60, including a fresh held-out case (new manager, 4/4) never used for a fix. The model keys keyless facts itself; the misses were updates it never saved. One end-of-turn step now saves when the user asked to remember or said a recalled fact changed. It fired in 25 of 60 trials, so this reliability is the harness's as much as the model's.

Long task, live

Ten functions, 12-step stretches: continuation fired in all five runs, with no "Continue". The work budget now grows with it (it had stopped one run at step 59), and re-reading a just-edited file is no longer a "repeat". Best run: 10/10 in 30 steps.

Environment found

The sandbox Python has no pytest, and pip installs into another interpreter. That hid progress in two runs; the case now ships a plain runner. Next priority: tell the agent how to test Python projects.
