The reproduced failure

Before (Gemma 4B)

"What's EchoSpeak's latest updates? github.com/Ty0x7/EchoSpeak/pulls" → a broad web search → read the github.com/Ty0x7 profile → cited it → "I can't access the pull requests."

Now

The link is read before the model's first call, through GitHub's API: PRs #106, #105, #104 with titles, states, dates and links are in context. One API request, no scraping, no search. The cited PRs are checked against what was read.

Evidence, not just URLs

Supported

Read this turn (or earlier in the chat), loaded properly, and covers the question. An API listing's own records count.

Seen only

Appeared in search results but was never opened: a lead, not support.

Unsupported or unknown

Opened but failed, blocked or off-topic, or never retrieved at all. The answer gets one request to fix it.

Limits and next steps

Limits

Relevance is lexical. JavaScript-only sites are detected, not rendered. The fixture set is small. Contradictions are weighed by the model (both sources are kept as evidence). Anonymous GitHub access allows 60 requests an hour.

Opportunities

A local cross-encoder rerank of the top 10. Native date filters from Tavily or Brave. More adapters (Wikipedia, arXiv, Stack Exchange). Showing "why this source" from the ranking reasons.

Your check: the exact PR question on Gemma 4B, the same question without the link, a version-specific docs question ("python 3.14 release notes"), and a comparison that needs several sources.
