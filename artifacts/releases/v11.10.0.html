Echo knows what it can do, and keeps working.

Echo knows its own version and what's on or off right now. You can queue or steer while it works, and it can send read-only research workers. Approvals ask less often, but nothing risky gets unlocked. An audit then closed the gaps those features opened, and small local models now make edits that land.

One request, start to finish

You send, queue or steer

Typing while Echo works queues a follow-up or adds to the task at the next safe step. Stop pauses the queue, even across a restart.

Echo knows what it can use

A section written by code lists what's ready and what's off, and what turns it on. Switches, Blocked apps and approvals apply to every tool.

Checked, then learned from

Results are graded from what the tools actually did. Lessons are tested against a random control. Refusals don't count as failures.

What changed

Security

  • Settings › Permissions now holds for Echo's own file editing and terminal tools. Through 11.9.3 they ignored those switches.
  • Always allow grants apply only to chats in the app, never to Discord DMs or routines.
  • Destructive commands wrapped in cmd /c, pwsh -c, node -e or python -c ask first, as do rmSync, os.system and iex.
  • Output from connected-app actions, and the tool descriptions servers write, count as outside content.

Working with Echo

  • Self-knowledge from the running app: version, desktop app or source build, OS, and a live list of what's on and off.
  • Blocked apps replaces the Allowed apps whitelist. Your old list became Favorite apps.
  • Always allow, and an Autonomous mode that holds risky actions for you instead of stalling.
  • A refusal circuit breaker: after repeated "no"s, Echo stops working around them and hands back to you.

Research workers (off by default)

  • The lead can send up to six read-only workers in parallel under one token budget.
  • A Workers card shows each one's status, steps, sources and time.
  • Only the agent you're talking to reads your steers. A worker that runs out of steps still reports what it found.

Small local models

  • An edit retyped with slightly different spacing, curly quotes or dashes still applies, but only if exactly one place matches.
  • A miss names the first line that differs, with spaces made visible, and which lines to re-read.
  • Builders on a local model see only their file, terminal and team tools. The rest load when needed.

Learning

  • Lessons are held back at random, so their benefit is measured against a control.
  • A redesigned Learning tab: a plain overview, three items per section, details on demand.
  • Research-worker runs, and actions you refused or blocked, no longer skew track records.

Documentation

  • A full-system audit with a competitive comparison against Claude Code, Codex, Gemini CLI, OpenHands and others.
  • An architecture record and a manual testing guide with copy-and-paste tests.
  • Release notes, this report and the atlas entry for 11.10.0.

What other harnesses do here

Claude Code's Edit tool matches exact text only. It works because Claude rarely misses, and because it teaches small edits and re-reading after a miss. Codex retries ignoring trailing spaces, then indentation, then quote and dash style. Gemini CLI adds a near-match step and an AI repair. EchoSpeak keeps exact matching first, adds Codex's passes and Claude Code's habits, and skips near-matching and AI repair: a near-match could change the wrong lines, and a repair costs minutes on a local model.
