About this history

This is a history of documented source updates, not a list of published installers. Missing/planned versions are not invented. The 11.8 work was integrated into 11.9.0, and the original 11.9 handoff architecture was later replaced by direct file discovery.

EchoSpeak 11

11.10.3
Echo notices when it's stuck on the screenClicks games and canvas apps where it sees them, never mistakes looking for clicking, drafts skills for you to approve, reads your .echospeak AGENTS.md, and runs the same commands on This PC as in the sandbox.
↗11.10.2
Echo can remind you, even from the trayReminders in plain words, one-time or repeating, in your chat and as Windows notifications; EchoSpeak can keep running in the system tray when closed.
↗11.10.1
Echo finds things better, and can't fake a resultOne Search by meaning setting with a multilingual model and sharper document results; grounded clicks, one recorded outcome per action, and document uploads fixed.
↗11.10.0
Echo knows what it can do, and keeps workingSelf-knowledge, queue and steer, read-only research workers, Always allow and Autonomous mode, and an audit that closed nine gaps. Small local models now make edits that land.
↗11.9.3
Your project work, clearly presentedHTML-only Work, widget/list views, stable previews and editable project names and logos. Documentation follows each project's own style.
↗11.9.2
Optional local speech and consistent setupVoice Settings and first-run setup share the selected speech provider. Drama-3 uses an optional verified audio.cpp runtime and separately downloaded models; later source work adds the reviewed documentation skill and file-based workspace.
↗11.9.0
Visual project work and integrated 11.8The project workspace brings reports and existing project resources together, with the 11.8 harness improvements carried forward. Its original manifest-sharing design was later replaced by direct file discovery.
↗11.8.0
A stronger native harnessNative computer-tool support, MCP OAuth/Apps/Tasks, quarantined reading, timing traces, retained tool output and signed remote-agent access extend the existing harness. This work was integrated into 11.9.0 rather than separately installed.
↗11.7.1
Screenshots the model can useScreenshot pixels reach vision-capable models and appear in chat. Approved bounded desktop actions use fresh observations, correct coordinate mapping and release held input on failure.
↗11.7.0
Enforced privacy and optional model choiceStandard, Private and Offline modes govern network access with a backstop. Optional smart model choice uses checked task history and only owner-listed models.
↗11.6.0
Discover and approve new connectionsEcho can suggest app integrations from setup guides and the MCP registry. The owner approves each connection, then a read-only call checks readiness; group work can continue while making progress.
↗11.5.1
Harden the existing trust boundariesHost commands after outside content require approval. Child processes lose inherited app secrets, file scope is tighter, and memory indexes gain integrity checks.
↗11.5.0
Ask, approve and stay in controlAgents can ask useful questions and surface readiness failures. Stop everything, outgoing limits, approved MCP servers and reviewed Agent Skills strengthen owner control.
↗11.4.1
Search dependencies reach the installed appThe frozen backend now includes the search and page-reading packages it needs. A build-time import self-check catches missing components before distribution.
↗11.4.0
Visible progress and inspected sourcesLive tool steps explain what is happening and summarize what finished. Research opens real pages before comparing results, while grouped activity stays compact.
↗11.3.0
A polished composer and Git-aware workThe composer, context meter, setup and Advanced settings become clearer. Coding agents inspect repository state and use scoped Git/GitHub actions through existing approvals.
↗11.2.0
Useful memory and a real artifact libraryMemory focuses on lasting facts rather than copied transcripts. Cleaner page rows, artifact search/version controls and evidence-led Learning views organize the results.
↗11.1.2
More room for conversationA slimmer sidebar and More/Less navigation reclaim space. Light-theme accents and a state-aware voice avatar improve the existing identity without changing the dark layout.
↗11.1.1
Remove stale backend files on updateAn old leftover module could break the new backend after installation. Cleaning the application backend before installing its replacement fixes that failure while user data remains separate.
↗11.1.0
A shared light and dark themeLight mode becomes the default, dark mode remains available, and theme choice applies across windows. First-run setup opens separately and leads into chat.
↗11.0.0
Learning from checked experienceTasks are graded from tool evidence and owner feedback. Bounded background reviews create lessons that remain advice, with review and retirement rules; this does not retrain the model.
↗

EchoSpeak 10

10.5.0
Quieter lists, clearer settingsExpandable three-item lists, grouped provider choices and meaningful empty states reduce clutter. Settings move beside the features they control without dropping saved values.
↗10.4.3
Cleaner Windows distributionEcho branding reaches the installer. Native shortcut maintenance replaces startup rewrite scripts, public guides become simpler, and updater/publisher verification stays distinct.
↗10.4.2
Chat actions and full conversation voiceCopy, read-aloud, edit and retry become normal message actions. Voice fills the conversation area, approvals and artifacts are polished, and model thinking controls reflect actual support.
↗10.4.1
Valid cloud tool continuationsParallel streamed tool calls keep separate identities, arguments and Gemini thought signatures. Readiness testing adds a harmless tool round-trip rather than treating catalog access as generation success.
↗10.4.0
Recover work and follow the evidenceDurable chat journals, saved generation job IDs, citation evidence, image editing and project continuity make work easier to resume. Setup verifies the selected model before opening the first chat.
↗10.3.2
Move around without losing the runEach chat owns its stream state, so in-app navigation no longer mixes or loses background output. Tables become readable and Creations adopts the shared page style.
↗10.3.1
Four cloud providers, live catalogsSaved keys, provider-specific adapters and live model catalogs improve switching between OpenAI, Gemini, Claude and Grok. The original Gemini Live path handled text/transcription, before later native audio work.
↗10.3.0
Create, research and get startedChat gains cloud/local image and video generation with a Creations library. Retained research evidence and guided first-run setup extend the existing systems.
↗10.2.0
A smaller, leaner applicationRetired runtime paths and terminal interfaces are removed. API and frontend responsibilities are split, while document embeddings become an optional ONNX download.
↗10.1.0
Group work follows throughTeams assign real tasks, check outcomes and continue unfinished work. Terminal jobs can run in the background, and saved-state claims require evidence.
↗10.0.3
Local model selection connects properlyRuntime detection, correct provider addresses and synchronized selections fix the path from a local model application to a working chat.
↗10.0.2
Pages and panels find their placeProject and library pages move into the main area. A resizable right panel keeps artifacts and activity beside the conversation.
↗10.0.1
Answers become usable outputsData-backed cards, richer formatting and versioned artifacts make answers easier to inspect, reuse and revise. The sidebar gains a stable place for the main pages.
↗10.0.0
One agent foundationChat, voice, channels and groups move onto the same tool-driven loop. Local voice setup, searchable history and desktop updates establish the shared application foundation.
