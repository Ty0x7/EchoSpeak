Recover work and follow the evidence

Durable chat journals, saved generation job IDs, citation evidence, image editing and project continuity make work easier to resume. Setup verifies the selected model before opening the first chat.

Historical change: this update introduced a Windows build workflow. It was later removed at the owner’s request; this page does not claim it still exists.

What changed

Windows launch and updating

  • Explicitly bundle LangChain's lazy modules, including the Runnable import that prevented the installed backend from starting.
  • Recognize permanent startup import failures and explain the missing dependency instead of repeatedly exhausting automatic recovery.
  • Production desktop builds use the Windows GUI subsystem.
  • Repair existing EchoSpeak desktop, Start Menu and taskbar shortcut targets after NSIS installation and on production launch.
  • Add a Windows GitHub Actions build with packaged self-checks, updater-signature verification, optional publisher signing and draft release assets.

Chat and creation recovery

  • The backend owns a chat run independently of its HTTP reader.
  • Record ordered output in a local two-day transport journal.
  • A backend restart preserves partial output and marks the run interrupted.
  • Saved Google Veo, MiniMax and ComfyUI job IDs can be polled after interruption, automatically on startup where possible or through Reconnect to existing job.

Research and projects

  • Click a retained research citation to open its supporting source in the existing Artifact / Activity / Research sidebar.
  • Edit working findings, open questions and conflicting findings; export a Markdown report.
  • Explicitly save working notes and up to 20 read sources to the chat's attached project.

Creation editing and setup

  • Edit existing generated images through Gemini image references or a local ComfyUI image-to-image preset.
  • Preserve original assets, verify reference hashes and chat/project scope, retain edit lineage and show related versions in Creations.
  • Introduce a monochrome Echo welcome with a brief spin and step transitions, consistent with the existing app.
  • Download and load supported starter chat models through an installed Ollama or LM Studio runtime after an explicit choice.
  • Verify the exact selected model's response before completing setup.
Verification recorded at the time
Focused checks cover disconnect/idempotency boundaries, saved remote-job polling, reference identity/scope, provider adapters, sidebar behavior and the setup-to-chat sequence. The Windows frozen backend build and its import self-check passed, including Runnable; recovery unit checks and shortcut fixtures passed too. The saved Gemini selection was a display name rather than an API model ID. Google rejected the saved credential with HTTP 401 (ACCESSTOKENTYPEUNSUPPORTED). Successful Gemini generation still requires a valid Gemini Developer API key and a model ID available to that account; it was not confirmed by this test. Windows release distribution still requires the final built and signed installer and clean installation/update checks. Real native microphone, GPU rendering and publisher-certificate validation remain machine-specific. Configure the existing signing key in GitHub secrets before using the new release workflow. An updater signature and an Authenticode publisher signature serve different purposes.
