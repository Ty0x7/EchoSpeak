Optional local speech and consistent setup

Voice Settings and first-run setup share the selected speech provider. Drama-3 uses an optional verified audio.cpp runtime and separately downloaded models; later source work adds the reviewed documentation skill and file-based workspace.

Later source work at the same 11.9.2 version added the reviewed project-documentation skill, automatic HTML/Markdown discovery and compact workspace headers (source commits 87d8a7e and 21b014a). These changes are separate from the original voice release notes below.

What changed

Voice Settings

  • Listening and read-aloud have separate sections.
  • Show only the selected speech provider's configuration.
  • Voice preview can be cancelled while preparing as well as while playing, and releases audio URLs when it finishes or closes.
  • Setup job completion refreshes saved paths without reopening Settings.

Optional Drama-3 speech

  • Verify a trusted audio.cpp executable for the actual Drama-3 speech loader, rather than checking only that an executable exists.
  • Link an existing compatible GGUF without copying it, or explicitly download one of six pinned quantizations with progress, SHA-256 verification, disk-space checks, cancellation and resume.
  • Build a pinned compatible audio.cpp source revision from Settings when the Windows C++ toolchain is already installed.
  • Configure CPU or NVIDIA CUDA, GPU index, CPU expert offload and an optional local reference WAV with its transcript.
  • Use the existing reply speaker button, previews, automatic read-aloud, standard voice conversations and governed project speech artifacts.
  • Native workers run without a visible terminal, inherit no app keys, and release memory after each request.

Startup and first setup

  • Existing users keep their completed/skipped setup state and are not sent through onboarding again.
  • Voice and creation setup start collapsed and remain optional.
  • Normal startup never loads Drama weights or starts its runtime.
Current workspace reference
Verification recorded at the time
Drama-3 is experimental and its downloads are approximately 16–24 GiB. Download size does not establish RAM/VRAM fit. CPU operation may be slow, and local conversation models share memory with speech. The release uses bounded WAV requests, unloading between clips; persistent warm-model and PCM streaming playback are not implemented. The focused backend checks passed 99 tests, including voice routing, native command construction, readiness, model-family checks, cancellation, Windows worker ownership, download integrity and existing provider/onboarding regressions. Frontend checks passed 153 tests, TypeScript and the production build; all 16 desktop contract tests passed. An isolated synthetic browser preview checked both themes at 1280, 960 and 768 pixels, path submission and pending-preview cancellation, with no card overflow or browser errors. Both the backend source startup self-check and a fresh PyInstaller backend's startup self-check passed; the bundled model license and notice were verified. Real Drama inference, sound quality, native compilation, GPU compatibility and the installed Windows update require owner testing. No paid providers or large model downloads were used during development. The technical audit includes source references, architecture diagrams, licensing and implementation decisions.
