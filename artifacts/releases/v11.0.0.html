Learning from checked experience

Tasks are graded from tool evidence and owner feedback. Bounded background reviews create lessons that remain advice, with review and retirement rules; this does not retrain the model.

Learning means evidence-based lessons and retrieval, not model retraining. The original notes explicitly leave real-model improvement unmeasured.

What changed

How agents learn

  • Every finished task is graded from what actually ran, not from what the agent says.
  • Claimed: the reply says it worked, but nothing backs it up.
  • Ran: tools ran and succeeded.
  • Checked: something was checked after the last change.
  • Double-checked: two different kinds of check, or two independent sources.
  • You confirmed: you pressed Worked.
  • Lessons come only from real evidence.
  • Every lesson starts unproven. It becomes proven after it helps in 3 or more checked tasks (75% or better).
  • Lessons are advice. An agent reads at most three closely related ones before a task (a loosely related lesson does more harm than good), labeled as advice that never permits anything.
  • Track records. Each agent builds a record by kind of task, for example "research 8/9 done".
  • Tool reliability. When a tool keeps failing, the agent gets a note to try another way instead of repeating it.

The Learning page

  • Waiting for your review: lessons that no agent reads until you approve them (see below).
  • Agents: each agent's track record, what it's good at and struggles with, and a switch to pause learning for that agent.
  • Lessons: what each one says, which tasks it came from, how often it helped or failed, and its full history.
  • Recent tasks: each task's grade and why it got it.
  • Reliability: how tools and search providers have been doing lately.

Safety

  • Learning can't loosen anything.
  • Lessons are screened in code before they're kept.
  • is about permissions, approvals, safety rules or secrets;
  • would skip or weaken tests and checks;
  • contains a link, a stored key or something that reads like a planted instruction.
  • Some lessons wait for you. A lesson goes to Waiting for your review when it was learned from a task that:
  • read web pages, email or other outside content;
  • changed tests or EchoSpeak's own files;
  • is about sending things for you.
  • Editing the checks is noticed.
  • Only your own requests teach. People reaching Echo through Discord, Telegram, Twitch or Twitter, and A2A calls, never do.
  • A failed model call teaches nothing, for example a missing key or a server that's down.
Setup and compatibility
- New data: learning/experience.db in your data folder. Deleting that file resets learning without touching chats, memory or settings. There's no other migration. - Cost: reviews use the agent's own model. With a cloud model, each review is one small paid request, bounded by Reviews per day. Set it to "None" to grade tasks without reviews.
Verification recorded at the time
Automated checks: - Backend: 56 tests for grading, lessons, feedback, review, the API and attacks. The existing agent and search suites pass with learning on and off. - Web: type checks and unit tests. Browser walkthrough against a scratch backend: - the Learning page; - approve and undo; - a refused edit; - Worked / Didn't work with a note; - the settings switch. Not yet measured: whether lessons improve results with a real model. apps/backend/scripts/evallearning.py runs that comparison (learning on, off, and a same-size control on held-out tasks). It needs a live model and should be run before publishing.
