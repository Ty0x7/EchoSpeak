EchoSpeak 11.10.3 · unstuck on screen

Echo notices when it's stuck on the screen.

Games and apps that draw their own buttons get clicked where Echo sees them, looking is never mistaken for clicking, and Echo can save what worked as a skill for you to approve. Includes 11.10.2's reminders and tray.

From "Control not found" to a click

A click by name fails

Now shown as failed, with why: the game draws its own buttons.

Looking isn't clicking

Screenshot tools say they only look. Three looks without acting gets a nudge to act or say what's blocking.

computer_action clicks what Echo sees, and checks the screen changed. Two misses: change approach.

What changed

Computer control

  • Failed clicks and "not found" count as failures.
  • Windows with no named buttons (games, canvases) are called out, with how to click them.
  • Echo is told when it keeps looking without acting, or acting without effect.

Skills

  • Echo can draft a skill from steps that worked; you approve it in Settings › Skills.
  • New bundled desktop-apps-and-games skill.
  • Add skills from .agents, .claude and .codex skill folders.

Your .echospeak folder

  • Like .claude and .codex: an AGENTS.md for your standing instructions and a skills folder.
  • An attached project's AGENTS.md or CLAUDE.md is followed too.

Terminal on This PC

  • Echo knows what's installed and how PowerShell differs from bash.
  • With Git for Windows, bash commands run on This PC like in the sandbox.
  • Risky commands still ask first.

Verification and limits

Backend (1287) and web tests pass, including a replay of the 11.10.1 Minecraft run through the real loop. A live retry with a real model is owner testing. A small model can still misjudge a small button's position; Echo now notices and changes approach instead of repeating itself.
